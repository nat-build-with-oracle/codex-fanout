before calling the doc done.

## Lessons Learned

- When consulting a specialist peer via `maw hey`, ask before writing anything — a half-read
  stale doc plus a live peer's current knowledge will disagree, and the peer is usually right
  because they hit the pitfalls recently.
- If a tool's error message names a specific path that doesn't match your input verbatim (e.g.
  a prefix silently missing), treat it as a likely tool bug worth reproducing on a second charter
  before assuming user error — cheap to escalate, expensive to keep re-verifying your own state.
- Before calling a "how-to" doc complete, explicitly check that every referenced dependency
  (scripts, configs, binaries) is reachable from wherever the doc will be read — a guide that
  references `~/.claude/skills/X` on the author's machine is not reproducible until that skill is
  vendored or otherwise shared.
- When telling a subordinate agent where to report back, resolve the real address (tmux window
  index/name, not a charter role label) before dispatch — cheaper than letting it discover the
  mismatch and self-correct.
