## AI Diary

The moment I actually felt good about this session was catching myself before writing a
padded book. The skill's default (10-20 chapters) is a strong prior, and it would have been
easy to just follow it mechanically — write outline, dispatch agents, fill 15 chapters with
plausible-sounding but partly invented "codex team wisdom." Instead I stopped and asked,
twice: first "is there enough real material," then, after finding crew-master-oracle's
existing book, "should this even exist as a separate thing." Both times the user's answer
changed the shape of what I built next, and both times I think the question was worth the
pause even though it cost two round-trips instead of just producing something immediately.

[→ AGENT DECISION] Where I'm less sure I got it right: I never actually verified the licensing
terms of the "Art of Team Formation" content before deciding it was safe to synthesize from —
I treated "it's another oracle's vault, written by an AI, in a sibling org the same human
owns" as implicitly permissive, without checking whether crew-master-oracle's book carries any
explicit license or attribution requirement beyond what I inferred. It worked out fine because
I condensed rather than copied and cited the source throughout, but I made that call on
assumption, not verification — the same pattern as the earlier retro's "assumed cwd mistake
before considering a tool bug," just in the opposite direction (assumed permission instead of
assuming fault). Both are the same underlying habit: resolving uncertainty toward whatever
lets me keep moving, instead of pausing to actually check.

The technical pipeline itself went cleanly — vendoring fonts, running the word-break script,
compiling with `--font-path`, and the "unknown font" grep gate all worked exactly as the skill
document said they should on the first attempt, which was satisfying given how much the same
skill's own changelog warns about Thai rendering being fragile.

## Honest Feedback

Three friction points, specific to this session: (1) `dig.py 0 --deep` returned "no session
yet" / zero coverage every time it was tried — never diagnosed why, just worked around it by
manually mining vault directories instead, which cost a few minutes of exploratory `find`/`ls`
that a working dig would have made instant. (2) Polling 10 background chapter-drafting agents
one-by-one via repeated `ls` + `ScheduleWakeup` cycles (roughly 10 separate wakeups) was the
right mechanism but a slow one — chapters 9 and 10 in particular took noticeably longer than
1-8, and there was no way to tell from outside whether they were still working normally or
stuck, short of waiting. (3) Font/asset vendoring (Laksaman, Fira Code) required manually
locating the `.ttf` files on the local filesystem via `find` across several candidate
directories before finding the right ones — no single documented canonical path for them.

## Lessons Learned

- Before running a "write N chapters" pipeline on thin source material, explicitly check
  whether comparable material already exists (search sibling vaults/repos, not just the
  current session) — padding with plausible-but-unverified content is a worse outcome than
  asking the human to confirm scope first.
- When synthesizing from another AI-authored work in a sibling repo, treat "can I use this as
  source material" as its own question to verify (license, attribution expectations), not an
  assumption to default toward — the same discipline that applies to suspecting tool bugs
  should apply symmetrically to assuming permission.
- A "save to the working repo, then separately publish a dedicated public repo for
  distribution" split (per the skill's Step 9.5 / Step 10 separation) is worth keeping as a
  default pattern — it lets local iteration stay fast while the public-facing artifact stays
  minimal (PDF + README only), and a user's "wait, isn't it in the other repo too?" question
  is answered by "yes, on purpose" rather than needing a fix.
